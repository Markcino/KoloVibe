## Mobile design audit and Home rebuild — 19 November 2026

Scope: every `live_*` screen and the shared state views, compared with the approved exports in `docs/designed/`. Home (M-017) was rebuilt first. This is a visual and layout audit from widget-test renders. **It is not device acceptance**; the physical iPhone run is `docs/engineering/iphone_e2e_checklist.md` (separate branch) and has not been executed.

**Method.** `apps/mobile/test/design_audit_test.dart` renders each screen with scripted repositories (no network) at 390 × 844 (status bar 47, home indicator 34) and at 375 × 667 (iPhone SE class, status bar 20, no indicator), each at 1× and 2× text, and fails on any layout exception. With `AUDIT_DIR` set it also writes a picture of the export beside the render. Home is additionally rendered at 320 × 568, at 1.5×, 2× and 3× text, and with a 336 pt keyboard inset (`test/home_dashboard_test.dart`).

```sh
cd apps/mobile
AUDIT_DIR=$PWD/build/design-audit flutter test test/design_audit_test.dart
```

**Evidence.** Pictures are written to `apps/mobile/build/design-audit/M-NNN_390x844.png` (export left, render right) and `…_375x667.png`. `build/` is ignored, so the pictures are regenerated locally with the command above, as with the 29 Oct captures. Captures omit the iOS status bar and the home-indicator bar that the exports draw. Dated 19 Nov 2026; Flutter 3.47.8.

**Status meanings.** *Match*: unchanged and equal to the export. *Fixed*: changed in this pass and now matches the export apart from the listed deviations. *Deviation*: a known difference remains, or the screen could not be captured here. **No screen is claimed as a pixel-exact Match.**

**What changed.** Theme tokens (`KoloVibeColors.line`, `KoloVibeRadii`, `KoloVibeText`; app bar, buttons, fields, chips, cards, dialogs, snack bars, dark surface); shared widgets in `lib/shared/widgets/kolo_components.dart` and `kolo_media.dart`; the Home dashboard (`lib/features/discovery/home_dashboard.dart`); the account flow, account hub, settings rows, catalog family, creator profile, Creator Studio surface, video detail metadata, Lone Stars heroes and ledger rows, and the system state panel. The bottom navigation uses the design’s weights and a clamped label scale. Layout fixes: long labels wrap instead of overflowing (wordmark, tiles, creator row), form errors show next to the primary button, form lists dismiss the keyboard on drag.

**Home (M-017).** Greeting uses the account’s real display name and the local time of day; signed-out shows “Welcome to KoloVibe” with Sign in. The hero is the first trending video; the trending row is the second; creators are the creators of trending videos, looked up through `GET /creators/{id}`; Follow uses the real follow state and rolls back on failure. Trending, creators and Following each own their loading, empty, error and signed-out state, so one failure never hides the rest. Nothing is invented: no durations, plays, avatars or sample creators.
