# R1 copyright review pipeline

Implemented contract proposal; copyright policy and operational activation need owner/legal review. Public operations are specified in DOC-205. No deferred streaming, ticketing or payouts are included.

Content owns `Video.rights_status`, append-only `OriginalityAttestation`, `PrescreenResult`, `RightsEvent` and SHA-256 first-seen evidence. Its existing signed Moderation-only endpoint adds `POST /internal/videos/moderation/rights`: `{video_id, command_id, report_id, event: claim|dismiss, actor_id, reason}` → `{applied:true}`. Command IDs bind payloads and make lost-result retries recoverable. Claims are independent of publication revision, so they do not invalidate an appeal's removal revision. Existing `apply` accepts optional `{copyright:true, actor_id, reason, report_id}` for copyright remove/restore and records attributable immutable evidence in the same transaction as state and receipt. Gateway cannot call these operations as Moderation. Dismissal/restoration clears the corresponding claim; old intake replays cannot reopen it.

Moderation extends the existing signed Gateway operation envelope with `copyright_report`, `counter_notice`, `copyright_status`; public Gateway routes bind actor and creator identity and reject caller-supplied creator IDs. Existing report/appeal decision routes retain assignment, MFA, independent appeal review and idempotent pending-delivery behavior. The strike projection is a one-to-one applied removal with optional restoration reversal. No automatic penalty or threshold is inferred.

Creators adds the signed Gateway-only operation `POST /internal/creators/onboarding/review_policy` using the existing `{actor_id, role, data:{}}` envelope. Response: `{account_id, creator_id, trusted, sample_percent, policy_version}`. It rechecks current eligibility and explicit active trust, excludes self-approval, and defaults to untrusted/100%/null. The media capability allows only this exact read alongside existing eligibility/ownership reads. No new peer credential, permission grant or deployment activation is introduced. An eligibility grant alone never enables automatic approval.

Upload intents now require `originality_attestation:{version:"R1-originality-v1",accepted:true}`. Gateway obtains account ID and trust policy from authenticated owning services, rejects client-supplied identity/trust, and signs the Content request. Content stores the policy snapshot with the immutable upload evidence. Upload retries retain the original timestamp and policy; a new reservation creates new evidence. Trust snapshots expire with the reservation. No historical consent is invented.

The worker reuses the merged `ExactHashProvider` and pluggable `ChromaprintProvider` interfaces (`screen(Media) -> ProviderResult`). SHA-256 is computed from actual source bytes. Existing raw Chromaprint extraction/alignment and confirmed-takedown fingerprint references remain the sole audio matching implementation. Missing fpcalc, invalid media or a provider failure is inconclusive and requires review; silent videos are identified by the existing audio-track check. No new binary, external provider or download is introduced. The existing optional safety/PDQ/music-screening path remains intact and can only add review holds; it cannot bypass the mandatory attestation/trust gate. Its findings/proposed decisions remain in `ScreeningRecord`; the final `copyright_gate` decision is recorded separately and is authoritative for publication.

Under the current lease/video lock, first-seen digest uniqueness serializes competing identical uploads. Flags and missing evidence always enter manual review. Clean untrusted and sampled trusted uploads enter review; clean unsampled trusted uploads get private moderation approval. The 100% default remains until approved policy changes. Do not present these checks as proof of copyright clearance. Rights reasons and fingerprint/reference data remain private; audit read redaction and no-raw-storage-key preview behavior remain unchanged.

Migration rollout: Content 0010 (after merged 0009 automated screening), Moderation 0006, Creators 0005. Additive models; legacy rights default to flagged without fabricated attestations. Prior not_recorded/muted/hidden/attested screening labels normalize to flagged because they did not establish per-upload consent. Muting/hiding remains a screening outcome, not an additional rights state. Drain pending moderation deliveries before migration. The Moderation migration derives historical strikes only from applied copyright report/removal codes with known creator attribution and their applied appeal restorations. Unknown legacy owners require authoritative ownership recovery and reviewed reconciliation; no owner or infringement finding is guessed. PostgreSQL and fixture SQLite guards prevent mutation/deletion of new attestation, screening, rights-event, digest, notice and counter-notice evidence. Roll back application activation or set sampling to 100%/disable trust while retaining evidence. The pre-attestation binary/client contract is incompatible with the five-state constraint and required upload consent: coordinate clients and use a compatible forward fix. Do not delete evidence or reverse these migrations without a reviewed retention/data plan.
