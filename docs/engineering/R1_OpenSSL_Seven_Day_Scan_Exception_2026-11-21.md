# Temporary OpenSSL image-scan exception — 21 November 2026

**Owner decision:** permit a narrowly scoped, seven-day scanner exception for the five High findings against the specific Alpine OpenSSL library packages in the R1 candidate. This is **not** a declaration that the packages are safe, fixed, or unreachable.

- **Scope:** exactly CVE-2026-124709, CVE-2026-107494, CVE-2026-121482, CVE-2026-84786, CVE-2026-107493 on each of `libssl3` and `libcrypto3`, apk version `3.5.9-r1` only (10 package/CVE matches). No wildcard names or versions. All other High/Critical findings remain blocking.
- **Start:** 2026-11-21 UTC. **Expiry:** 2026-11-28 UTC. The existing Python script test suite fails on/after the expiry date unless the exception is removed and remediated or explicitly renewed with a new risk decision. The exception policy does **not** remove itself automatically: expired entries must be deleted.
- **Observed evidence:** PR #121 CI run 44885310174 showed image-scan failures in shared service, staging web, and media-worker images. Grype matched the listed CVEs to `libssl3` / `libcrypto3` 3.5.9-r1 and reported no fixed apk versions in that scan.
- **Exposure and residual risk:** OpenSSL provides TLS and cryptographic functionality inside KoloVibe's runtime. Cryptographic and TLS parsing operations are reachable through legitimate service and client connections. The restrictive AWS staging deployment, private service networks, TLS verification, and authenticated gateway reduce direct attack surface, **but are not demonstrated mitigations for each individual CVE**. No claim is made that a vulnerable code path is disabled or that attacks are impossible. Treat all five High findings as open risks until an advisory-specific assessment and patched binaries are available.
- **CI enforcement:** the three Anchore image jobs retain `fail-build: true` and `severity-cutoff: high` on PRs and main. The exact-package ignore entries in `.grype.yaml` are the only OpenSSL exceptions. Preexisting FFmpeg exceptions remain governed by their separate evidence and expiration. No new FFmpeg finding is exempted by this decision.
- **Release boundary:** passing CI after these exceptions is a *conditional* scanner result, not unrestricted security acceptance. Production deployment remains disallowed pending vulnerability remediation and security review; any restricted staging deployment requires existing rollout authorization, digest pinning, and rollback controls.
- **Remediation:** monitor Alpine security advisories daily; once a patched `libssl3`/`libcrypto3` build exists, refresh and pin the base image, rebuild all three images, rescan, remove these ten ignore entries, and rerun CI and local tests. If no fix exists at expiry, the scanner should fail closed until a new documented authorization explicitly renews the risk (do not silently extend expiry).
- **Owner follow-up deadline:** 2026-11-28 UTC.

Sources for the observed matches: GitHub Actions job logs for run 44885310174, PR #121. This document records the scoped risk acceptance; it is not evidence of exploitability or a vendor fix-status verification.
